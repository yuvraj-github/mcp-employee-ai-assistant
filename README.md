# Employee AI Assistant

A small employee-directory assistant that combines a browser chat interface, Claude, the Model Context Protocol (MCP), and a MySQL database. Users can ask questions in natural language; Claude can discover and call the read-only employee tools exposed by the MCP server and use their results to answer.

## Features

- Browser-based chat UI served by Express.
- Chat requests are validated for a non-empty question with a maximum length of 2,000 characters.
- Claude Haiku 4.5 can select from MCP tools, receive their results, and continue composing a response (up to five tool-use rounds per question).
- Four read-only employee-directory tools:
  - Look up one employee by ID.
  - List all employees or filter by department.
  - Count employees in a department.
  - List distinct departments.
- MySQL queries use parameter placeholders for user-supplied values.
- Assistant Markdown is sanitized in the browser before it is rendered.
- Graceful MCP client shutdown is registered for `SIGINT` and `SIGTERM`.

## MCP server and MCP client

The **MCP server** in `server.js` advertises the employee tools and handles tool calls. It uses `StdioServerTransport`, so an MCP host starts it as a child process and communicates with it over standard input/output. The server validates tool inputs and delegates database work to `tools/employeeTools.js`.

The **MCP client** in `services/claudeService.js` is part of the web application. It launches `server.js` using Node.js and `StdioClientTransport`, connects to it, and asks it for its available tools. The client passes tool calls from Claude to the server and returns tool results to Claude.

## Available MCP tools

| Tool | Input parameters | Behavior |
| --- | --- | --- |
| `get_employee_details` | `employeeId`: positive integer (required) | Returns `id`, `name`, `department`, `designation`, and `joining_date` for the matching employee, or the text `Employee not found`. |
| `list_employees` | `department`: string (optional) | Lists `id`, `name`, `department`, and `designation` for all employees, or filters by an exact department value when provided. |
| `count_employees_by_department` | `department`: string (required) | Returns the employee count for the exact department value. |
| `get_departments` | No parameters | Returns distinct department values ordered by department. |

The queries expect an `employees` table with the columns `id`, `name`, `department`, `designation`, and `joining_date`. The included [`database.sql`](./database.sql) defines that table and provides fictional demo records.

## How Claude discovers and executes tools

1. When the web process starts, `connectMcp()` opens the stdio connection and calls the MCP client's `listTools()`.
2. The returned names, descriptions, and input schemas are converted to the tool format supplied to Anthropic's Messages API. Tool definitions are discovered from the running MCP server; they are not separately hard-coded in the Claude service.
3. On each question, the service sends the conversation and available tools to Claude using the `claude-haiku-4-5` model.
4. If Claude responds with `tool_use`, the service calls the named MCP tool with Claude's input.
5. The MCP result is returned to Claude as a `tool_result`. Claude may then answer or request another tool; this loop is capped at five rounds.
6. When Claude returns without a tool call, the service sends its text response to the browser.

## Installation and setup

### Prerequisites

- Node.js 18 or newer and npm.
- A MySQL server. The demo database and fictional employees can be created by importing [`database.sql`](./database.sql).
- An Anthropic API key with access to the configured Claude model.

### Install dependencies

From the project root:

```sh
npm install
```

### Configure environment variables

Copy `.env.example` to `.env` in the project root and replace every placeholder with your own local values. Do not commit `.env`.

```dotenv
ANTHROPIC_API_KEY=replace_with_your_anthropic_api_key
DB_HOST=replace_with_your_mysql_host
DB_USER=replace_with_your_mysql_username
DB_PASSWORD=replace_with_your_mysql_password
DB_NAME=replace_with_your_mysql_database
```

These are the environment variables read by the application. The MySQL pool uses the default MySQL port because no port option is configured in `config/db.js`.

### MySQL configuration

`config/db.js` creates a `mysql2/promise` connection pool using `DB_HOST`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME`. Import the included demo schema and records with phpMyAdmin:

1. Start MySQL and sign in to phpMyAdmin.
2. Create a database for the demo, for example `employee_ai_assistant`.
3. Select the database in the left navigation panel.
4. Open the **Import** tab, choose `database.sql` from the project root, and click **Import** (or **Go**, depending on your phpMyAdmin version).
5. Set `DB_NAME` in `.env` to the database you created. Ensure the configured database user has permission to read the `employees` table.

The SQL creates the `employees` table with `id`, `name`, `department`, `designation`, and `joining_date` columns and inserts fictional demo records. Import it once into an empty demo database; the sample IDs are fixed for the examples below.

## Starting the application

The package scripts are:

```sh
npm start       # node webServer.js
npm run dev     # node --watch webServer.js
```

The web server serves the chat page at `http://localhost:3000` and accepts chat requests at `POST /api/chat`.

The MCP subprocess path is correct: `claudeService.js` resolves the directory containing `services/` and moves up one level to the project root, then launches the root-level `server.js`. This works independently of the current working directory.

## Testing MCP tools with MCP Inspector

The Inspector can launch and test the MCP server directly without starting the web application.

1. Configure the `.env` values and make sure the MySQL database/table are available.
2. From the project root, start the Inspector:

   ```sh
   npx @modelcontextprotocol/inspector node server.js
   ```

3. Open the local Inspector URL printed in the terminal.
4. Connect to the stdio server, list its tools, and call a tool with test input. For example, call `get_employee_details` with an existing positive `employeeId`, or call `get_departments` with an empty input object.

The Inspector tests the MCP server and database tools; it does not test the Express chat UI or Claude API integration.

## Security considerations

- Keep `.env` out of version control. `.gitignore` excludes `.env` and `.env.*` while allowing an optional `.env.example`.
- Never put an API key, database password, or real employee data in this README or source control.
- The SQL queries bind user-provided values with placeholders rather than concatenating them into SQL.
- MCP tool inputs are schema-validated, and the chat endpoint limits the JSON body to 16 KB and the question to 2,000 characters.
- User messages are inserted as text in the browser; assistant Markdown is sanitized with DOMPurify before rendering.
- The current web API has no authentication, authorization, rate limiting, or transport security configuration. Do not expose it publicly with access to real employee data without adding appropriate controls.
- Use a database account with the minimum required read permissions. The included tools perform reads only, but anyone who can reach the chat endpoint can request data exposed by those tools.
- Treat employee records and prompts as sensitive information, and review applicable privacy and data-retention requirements before sending questions to an external AI service.
